## Changes

- Cast Auto mode prefers direct receiver-compatible playback; explicit HLS
  compatibility mode requests stereo AAC. Decoder capabilities come from Android,
  browser playback checks, and Cast load/error probing. Unknown Cast devices do
  not require a manual profile choice; the Device control is an optional override. These are alternatives for testing
  the reported Cast-only lip-sync issue; a hardware fix is not yet confirmed.
- Cast status no longer automatically reopens the expanded controller. Paused
  movies are preserved instead of being replaced by browse artwork.
- Series and episode playback use the actual playable Jellyfin episode ID.
  Automatic next-episode playback crosses seasons and excludes missing episodes.
- Previous/Next and Episodes controls work locally and on Cast. Autoplay is an
  explicit, persistent setting. Cast prepares the next episode before loading
  the queue and appends up to 50 upcoming episodes to the receiver. Prepared
  receiver queues continue without the player screen; queue preparation itself
  requires the app process to remain alive.
- Cast subtitles can be selected or disabled. Language preference also applies
  to queued episodes. Play Here preserves the current position and pause state.
- Current episode and position survive Activity recreation. Playback format
  changes preserve position; delayed retries cannot target a released player.
- Search replaces its own results and pending browse work cannot overwrite it.
  Category requests and trailer WebViews are cleaned up on navigation.
- Catalogs recycle visible cards and fit available width. Sort by title or year,
  prioritize unwatched titles, filter watched/unwatched/in-progress, and mark
  titles watched or unwatched. Options are separated by server, profile and type.
- Server fallback remembers the reachable endpoint for later API/media requests.
  My List retains its identity across local/external endpoint changes.
- Household credentials are restricted to the exact HomeStream origin, including
  media redirects and subtitle/HLS requests. Download URLs no longer receive the
  token in query parameters. HLS playlists are rejected as single-file downloads.
- Production encryption requires Android Keystore. JVM tests inject an in-memory
  test key. Devices that used the old plaintext-key fallback need to pair again.
- Discovery selects a server for authenticated pairing instead of attempting an
  anonymous device registration. It closes HTTP connections and keeps
  deduplication state scoped to one scan. TV navigation scrolls to all actions.
- Version 1.1.0 / code 3. Release builds require an explicit signing configuration;
  they are no longer signed with the debug key.

## Android TV follow-up and launcher Continue watching

- TV Back restores the prior browse view, scroll positions, search text and focused
  card. The navigation rail opens actual server settings. Async content loading
  no longer takes focus away from the rail; details and rotating hero actions
  receive explicit focus styles. These behavior changes are TV-only.
- TV playback reports per-decoder resolution and H.264/HEVC profile bounds to the
  backend. It keeps native MKV/container support and compatibility conversion.
- Added the platform Watch Next integration for compatible Android TV/Google TV
  launchers. Movie/episode cards contain progress, duration, artwork and an explicit
  deep link to resume the actual item. Entries are scoped to the current server
  and HomeStream profile; only one episode per series is published.
- TV playback reports update launcher progress and remove completed cards. App
  startup and a persisted, network-constrained JobScheduler task refresh Jellyfin
  resume history (periodic work runs approximately every 15 minutes, subject to
  Android scheduling). Offline failures preserve existing cards. Dismissed cards
  are respected; profile changes and disconnect clear stale cards.
- The launcher controls card visibility/order. Writing Watch Next data does not
  guarantee placement on every Google TV launcher/version. This integration does
  not submit a public Google Media Actions catalog or commercial partner feed.

Manual TV checks (no interactive testing was performed during implementation):
1. Open a title from a scrolled library/search, press Back, and check focus/position.
2. Move to the rail while content loads; check focus stays there. Check all details
   actions have visible focus, including changing the details tab.
3. Open Settings and check server information and external URL are accessible.
4. Play compatible 1080p and incompatible 4K/profile titles on an HD TV device;
   inspect playback details for direct play versus required conversion.
5. Watch a movie/episode for over two minutes, leave playback, then check launcher
   Continue watching. Select its card and verify the correct title resumes.
6. Finish/mark watched, switch profile, disconnect, and dismiss a launcher card;
   confirm stale/completed/dismissed cards do not return unexpectedly.
7. Change progress on another device, reopen the TV app (or allow scheduled sync),
   and verify the launcher progress refreshes. Offline sync should preserve cards.
